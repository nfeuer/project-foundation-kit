# Changelog

All notable changes to the kit, newest first. Sections are generated by the
`release` skill from conventional commits (`docs/COMMIT_CONVENTION.md`).

## [v2.1.0-alpha] — 2026-07-31

Claude Opus 5 / Sonnet 5 skill refresh across the kit's dispatch, model-routing,
and review/reporting conventions. Full wave-by-wave record:
`docs/plans/claude5-skill-refresh.md`.

### Features
- **skills:** retire the "1% rule" doubt-threshold dispatch for the
  trigger-index contract `SPEC.md` §7 already names — scan the index, invoke
  on a matching row, N/A when a capability toggle is off (ADR-0001)
- **kit:** profile-backed model routing — new `models.*` keys (`code`,
  `code_light`, `plan`, `mechanical`, per-role `effort`) in `.claude/kit.yaml`
  and all five `presets/*.yaml`, a `## Model routing` table in
  `using-the-kit`, and `kit-doctor` check 16 flagging retired or
  date-suffixed model IDs (ADR-0002)
- **skills:** scope-boundary sentences in the 11 measure-and-report skills
- **skills:** recall-first review instructions in `pre-pr`,
  `observability-check`, and `config-audit` — report every finding with a
  confidence/severity rating instead of silently filtering
- **skills:** current model IDs and pricing across the LLM-ops skills
- **skills:** length-calibration guidance in the document-producing skills
- **skills:** `adopt-existing-project`'s duplicated hooks-walk heredocs merged
  into one copy-runnable script

### Adopter note
`CLAUDE.template.md` is merged into a project's `CLAUDE.md` at bootstrap, not
kit-managed — this refresh does not reach it. Hand-update the old 1%-rule
paragraph in your own `CLAUDE.md`, then run `kit-update` → `kit-doctor` →
`config-audit`.

## [v1.3.0] — 2026-07-06

Version jumps from v1.1.0 to v1.3.0 to track `kit_version`, which both features
below bumped once each.

### Features
- **observability:** logging standard covers every process type, not just API
  calls — per-process-type event catalog in `docs/LOGGING_STANDARD.md`,
  `log_operation` context manager, observability-check and reviewer-agent
  coverage for jobs/consumers/pipelines (#3)
- **skills:** `logging-init` — interactive, evidence-based logging
  initialization: probes existing logging, classifies the repo, asks batched
  questions, wires a stack-mapped setup additively; recorded in the new
  `logging` block of kit.yaml (#4)
